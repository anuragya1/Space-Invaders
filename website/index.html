What makes it interesting

The classic loop is still there. The systems around it are the point.

01

Director AI

The game watches pressure during a run and can shift into beats like Relief Window or Pressure Surge. It is a small system, but it gives the arcade loop a bit more personality.

02

Replay system

Runs can be saved as input logs and played back through the same simulation. That makes replays useful for players and useful for debugging determinism.

03

Boss waves

Boss encounters break up the normal wave rhythm. They also give the renderer, audio, HUD, and Director systems a clear moment to show what they are doing.

04

One simulation, many inputs

Keyboard, AI, replay, and co-op sources all feed the same action mask path. That keeps the core game easier to test and harder to accidentally split into separate behaviours.

Technical notes

The project is built around deterministic game state.

The simulation owns the rules, input sources feed actions into it, and rendering/audio observe the result. That structure keeps replays, AI, co-op, and tests tied to the same behaviour.

Simulation

Fixed update logic for player, aliens, bullets, powerups, bosses, scoring, and lives.

Input sources

Keyboard, replay, AI, and co-op all produce action masks for the same game path.

Replay files

Stored input frames make playback and determinism checks possible.

SDL3 presentation

Sprites, particles, screen shake, audio, menus, and HUD feedback sit on top.

Development journey

Where it came from.

I originally built this as my final-year college project. At that point, the goal was to get the arcade loop working. I kept going because the project became a good way to learn game architecture, deterministic testing, replay files, releases, and maintainability.

Roadmap

What I would rather improve next.

  1. Package SDL3 builds properly Make the player-facing build easy to download on Windows, Linux, and macOS.
  2. Keep replay playback visible Make replay files easy to create, find, verify, and showcase from SDL3.
  3. Harden the event flow Keep simulation, audio, achievements, telemetry, and presentation from tangling together.
  4. Add only high-value gameplay Prefer memorable Director and replay moments over piling on random features.

Contribute

Small, focused pull requests are welcome.

Good areas to help: SDL3 packaging, Linux/macOS validation, replay tooling, tests, website media, accessibility, controller input, and docs that explain real tradeoffs without over-explaining C++ basics.
